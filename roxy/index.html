The Assistant

An agent that works through the same door as you.

Roxy’s Assistant is a Claude agent loop with eleven tools. It can look up command help and the help docs, describe the scene, inspect a node, run Python, look at the viewport, load a skill, and split a reference sheet into view planes. Whatever it builds, it builds with the same registered commands the menus use, so there is no second code path to drift out of sync.

  • Ask mode reads, Act mode builds. Ask mode inspects the scene; Act mode builds in it through the same commands.
  • One turn is one undo step. Grouped commands, as in Maya and Houdini.
  • Money needs a click. Anything that spends credits or API cost shows an approval card first, with per-turn and monthly caps.
  • Your key, your machine. It uses your own API key, kept in the system keychain. Threads are saved per scene.
  • It sees what changed. Each turn it is given the scene diff since its last turn, straight from the change bus.
  • It reads images. Paste, drop or pick an image or a PDF. A reference sheet splits into lined-up view planes.
Real scenes

Production USD in, path-traced frames out.

Open Pixar’s Kitchen_set (1,788 meshes, 536,949 triangles) in 1.4 s. Up-axis, units and matrix conventions are resolved at the import boundary, prims keep their transforms, and every import reports what it could not carry across. UsdPreviewSurface materials come across with their textures, drawn in the viewport and streamed on demand into the path tracer, and USD cameras and UsdLux lights come in as Roxy cameras and lights. Gaussian-splat captures (PLY or SPZ) load as ordinary selectable scene objects: 305,872 splats in 0.08 s.

Procedural modelling

Every shape is a node graph, and every edit stays live.

Primitives, poly operators, curves (sweep, revolve, loft), terrain with erosion, scatter and copy-to-points. A VEX-style wrangle node compiles per-element code to GPU kernels. Menu tools insert their node into the shape’s chain, so nothing is ever baked. Deformers stack on top and stay live: bend and twist, lattice, wire, cluster and soft modification, delta mush and shrink-wrap, with painted weights. Voronoi fracture, UV unwrap and projection, and booleans that keep quads. Blueprint tools let you place reference images, trace curves on them, then sweep or loft the sections, with typed units: 1.2 m becomes 120 in a centimetre scene.

Look and render

A path tracer with the production features in it.

Principled BSDF with energy conservation, shader graphs, sun and sky, and UsdLux lights with exposure, spot shaping and light linking, sampled through a light BVH. Subsurface random walks, photon-mapped caustics, height fog, displacement, motion blur, render passes and a guided denoiser, on a Taichi wavefront tracer with a two-level BVH. 140 million rays per second at 1080p on an M1 Max. A Kitchen_set still at 1600 × 900, 256 samples, denoised, takes about 3.5 minutes.

Scripting

Everything is a command.

313 commands in 24 categories live in one registry. The Script Editor, the Python console, the menus, the shelves and the Assistant are all generated from that list, and a generated .pyi file gives editors completion. A slider drag is a command too (beginEdit, previewEdit, commitEdit), so the UI never changes the scene by another route.

Architecture

The UI is a view of the scene, never its owner.

Eight Python packages, about 254,000 lines excluding tests, layered so dependencies run one way: the UI and the Assistant on top, the roxy command layer beneath them, then a Qt-free scene model, with geometry and maths kernels at the base. Every edit runs through one command layer; views only listen.

Five rules the codebase follows

One Qt-free model.
The scene and its session hold all state and import no Qt. The UI adapts to it.
Every change is a command.
Each verb is registered once. Menus, shelves, the Script Editor and the Assistant all come from that list.
Undo is grouped commands, not snapshots.
An Assistant turn is one group, so one Undo removes the whole turn.
Formats stop at the boundary.
USD is converted on import, not held. It has no stable component ids, so it cannot host procedural editing.
The data model outlives the renderer.
The renderer reads an immutable snapshot, so the Taichi kernels can be replaced by C++ without changing the model.

How it was built

Spec first, audited often.

Roxy has been in development since 30 April 2026: 4,624 commits and 637 merged pull requests, with 17,299 automated tests. Each feature gets a written design spec before any code, work lands as reviewed pull requests, and the codebase is audited periodically.

I own the architecture and the direction. I wrote the original path tracer and the scene graph myself, and I made the organizational decisions that shape the codebase. Claude Code has implemented my designs since then, working through them with me in discussion. The code audits are also Claude Code’s work.
